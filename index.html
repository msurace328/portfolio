    What I build

    Four kinds of work, all in production. Each one connects a system that holds truth about a person to a system that grants them something.

    Lifecycle automation from the HR system of record

    Onboarding and offboarding run from HR truth through Okta lifecycle workflows and SCIM, with custom connectors in Okta Workflows for the apps that need them. Just-in-time grants expire on their own. Access reviews feed SOX evidence instead of generating it after the fact.

    Device posture wired into identity

    Intune compliance baselines for BitLocker and Secure Boot plus minimum patch levels feed Entra ID Conditional Access, so a machine out of compliance is blocked from corporate resources. Jamf Pro syncs macOS into the same policy. At Zineniac, a multi-OS fleet ran in Fleet, from enrollment automation to compliance policies.

    Okta and ConductorOne are managed in Terraform with plan on the pull request and apply from CI. Terraform for AWS and GCP is scanned with Checkov and tfsec before anything lands. A change to who can reach what is reviewed the same way a change to the product is.

    Empreinte

    A trust and access platform I build as sole engineer, in the open. Next.js and React in TypeScript, with the controls I would want to audit if someone else had written it.

    • Hash-chained audit log, computed server side. Every accept or override is written under the operator's identity with the hash of the entry before it, so tampering is evident.
    • Agentic intake with a human in authority. A tool-using agent on the Claude API scores and dispositions applications; a person holds the decision and every outcome is logged.
    • Role-based access control and a test suite that checks the SHA-256 implementation against NIST vectors. That suite caught a real timezone bug.
    • Security pipeline on every push to main: the test suite and CodeQL, then a gitleaks scan of the full history and npm audit at a high-severity threshold.

    How I work

    Three habits that show up in everything above.

    Evidence before claims

    A control that passes a test against a configuration nobody owns is not a control. I look for the system of record first and build the dashboard on top of it, not the other way around.

    Review everything that grants access

    Okta and ConductorOne live in Terraform behind peer review. AI reviews pull requests that change Okta permissions. Code that AI wrote gets verified before it ships, same as mine.

    Leave the standard behind

    Runbooks and a written operating standard, plus rules files for the tools the team uses, so the next person can run what I built without me in the room.
